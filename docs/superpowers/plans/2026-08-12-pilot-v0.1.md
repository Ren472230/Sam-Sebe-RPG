# Pilot v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first persistent, locally playable vertical slice that demonstrates deterministic free-form-compatible actions and one complete Behavior → Achievement → Ability progression loop.

**Architecture:** The core is a small Python package with deterministic domain logic, SQLite persistence, an append-only event log, and a progression service. UI and parsing are adapters: the core consumes `CanonicalAction` objects and has no dependency on Discord or any LLM. A local CLI is the first playable surface; a Discord adapter can be added after the core loop passes tests.

**Tech Stack:** Python 3.12+, standard library (`dataclasses`, `enum`, `sqlite3`, `random`, `argparse`), pytest as the only initial dev dependency.

## Global Constraints

- Python 3.12+.
- Standard library first; pytest is the only initial development dependency.
- sqlite3 directly, no ORM.
- dataclasses/enums for domain models.
- one process.
- no Docker requirement.
- no paid service requirement.
- Only deterministic simulation code may mutate authoritative world state.
- LLM/parser output is always non-authoritative input that must pass validation.
- No classes, levels, fixed skill trees, quest system, factions, full combat, vector DB, RAG, web frontend, or MMO infrastructure in v0.1.

## Deferred only after the local working model passes

These are explicitly outside the first implementation pass and become the next work only if the deterministic loop is sound:
- `FEED`, `GIVE`, `USE` and raven trust progression;
- natural-language LLM parser provider (e.g. Ollama structured output);
- Discord adapter and bot token configuration;
- lazy real-time world catch-up beyond explicit `WAIT`;
- multiplayer concurrency and social dependency tests.

## Completion checklist

Pilot working-model implementation is considered complete when:
- [ ] clean checkout installs locally;
- [ ] all tests pass;
- [ ] SQLite restart preserves world/progression;
- [ ] LOOK/MOVE/TAKE/DROP/THROW/WAIT are playable;
- [ ] all action outcomes are authoritative deterministic results;
- [ ] event evidence is persisted;
- [ ] repetition alone cannot unlock the first specialization;
- [ ] varied competent throwing can unlock achievement + `aimed_throw`;
- [ ] mechanic validator blocks out-of-range effects;
- [ ] CLI allows founder play without Discord/LLM;
- [ ] demo script proves the complete vertical loop.
