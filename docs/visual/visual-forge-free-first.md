# Visual Forge: free-first production policy

## Цель

До playable vertical slice не строить отдельную платную AI-инфраструктуру. Использовать встроенное создание/редактирование изображений ChatGPT для новых пикселей, а все операции, которые могут быть детерминированными, выполнять кодом.

## Критический путь

1. Не перегенерировать целый Start Village.
2. Один canonical asset = один независимый файл/слот.
3. Принятые пиксели считаются замороженными.
4. Локальная правка проверяется маской: изменения вне маски запрещены.
5. Сцена собирается из слоёв Python-скриптом.
6. GitHub проверяет материализованные runtime-файлы на каждом изменении visual production ветки.

## Реальное состояние на момент внедрения

Ветка `dev/production-visual-integration` уже содержит честную partial-production интеграцию:

- активный L3: `village/L3_ARCHITECTURE_PARTIAL.webp`;
- активный L4: `village/L4_GAMEPLAY_PARTIAL.webp`;
- остальные слоты используют fallback/greybox до появления подтверждённых байтов;
- parallax остаётся выключенным, пока нет безопасных независимых слоёв с запасом по краям.

Visual Forge не заменяет эту схему. Он добавляет над ней повторяемый инструментальный контракт.

## Бесплатный контур

```text
ChatGPT image generation/edit
        -> accepted PNG asset
        -> inspect / mask validation
        -> deterministic compose
        -> production manifest
        -> GitHub automated gate
        -> game runtime
```

Внешний платный API в этой цепочке не требуется.

## Правило materialization

Исторический статус `LOCKED` или `ACCEPT` не означает, что файл физически доступен текущему runtime.

Поэтому реестр разделяет:

- `active` — ассет реально участвует в текущем runtime derivative;
- `accepted-unmaterialized` — визуально/технически принят ранее, но байты не лежат в текущем репозитории;
- `candidate` — кандидат есть, но canonical promotion не доказан;
- `rejected-slot` — файл существует, но не соответствует конкретному независимому слоту;
- `unmaterialized` — доказанных repository bytes сейчас нет.

Это предотвращает ложное ощущение, что 14/14 уже физически доступны.

## Следующий production-приоритет

Не генерировать новые варианты уже принятых объектов. Сначала материализовать в репозиторий существующие locked-ассеты, если их raw PNG удаётся восстановить. Только доказанный gap разрешает новую генерацию.
