## Продуктовая цель

Довести существующий браузерный вертикальный срез Sam-Sebe-RPG до цельного, устойчивого и демонстрируемого опыта маленькой живой деревни, где мир продолжает существовать, персонажи действуют и помнят события, знания распространяются причинно, а игрок может свободно вмешиваться.

## Текущая граница продукта

Текущий продукт – воспроизводимый браузерный вертикальный срез, а не содержательно завершённая RPG.

В текущую границу входят:

- Start Village и таверна;
- Living World;
- Living NPC;
- Social World;
- Living Conversation;
- причинно ограниченная передача знаний;
- движение и пространственное взаимодействие игрока;
- TAKE / GIVE / WAIT;
- квест Орена с дровами;
- бытовая ситуация Миры и Каспара;
- прибытие Талена и гостеприимный цикл с хлебом;
- сохранение состояния SQLite;
- браузерный клиент Phaser;
- временный полный SVG-набор для текущего демонстрационного среза;
- автоматические серверные, браузерные, Windows и воспроизводимые проверки.

Основная целевая среда представления – настольный компьютер и читаемость для зрителя. Мобильный режим остаётся поддерживаемым запасным вариантом.

## Критерии успеха текущего этапа

Текущий интеграционный кандидат считается технически готовым к человеческой оценке, когда один точный итоговый SHA проходит весь обязательный набор проверок и отсутствуют подтверждённые технические блокеры уровня выпуска.

После этого требуется отдельная реальная человеческая проверка понятности управления, ощущения игры и качества представления.

## Архитектурные инварианты

- SQLite и детерминированные Python-сервисы владеют каноническими фактами, инвентарём, локациями, отношениями и физическими последствиями действий.
- FastAPI предоставляет игровому клиенту существующие авторитетные интерфейсы.
- Языковая модель генерирует язык и узко валидируемые разговорные метаданные и не получает прямой власти над физическим состоянием мира.
- Утверждения игрока не превращаются автоматически в объективные факты мира.
- Знания NPC распространяются через причинные маршруты и сохраняют происхождение.
- Персистентность и детерминированное воспроизведение остаются обязательными свойствами.
- Игровой клиент сохраняет существующее разделение между серверным каноном и пользовательским представлением.
- Исправления браузерной навигации для текущей стабилизации сохраняют реальное физическое управление и не маскируют дефекты телепортацией, отключением столкновений, изменением скорости игры или искусственным увеличением глобальных тайм-аутов.

## Разрешённая автономная область

ChatGPT может самостоятельно:

- исследовать состояние GitHub и действующих планов;
- исправлять подтверждённые дефекты в рабочей ветке;
- реализовывать следующие задачи утверждённого плана текущей интеграции;
- добавлять и уточнять проверки через воспроизводимые доказательства;
- обновлять управляющие файлы по фактам;
- создавать отдельную ветку для безопасного изолированного эксперимента;
- корректировать ближайший порядок задач, если новый подтверждённый блокер меняет зависимость.

## Требует владельца

Отдельное явное разрешение требуется перед:

- слиянием PR #53 или любой другой ветки в `main`;
- публикацией релиза;
- разрушительной миграцией сохранённых данных;
- удалением значимого пользовательского содержимого;
- изменением секретов, оплаты и внешних учётных записей;
- включением платного внешнего сервиса;
- сменой фундаментального технологического стека;
- значительным расширением границы продукта.

## Обязательные проверки

Перед утверждением технической готовности одного кандидата на одном точном SHA должны быть зелёными:

- `Visual Forge Gate`;
- `Stream Slice Gate`;
- `Prototype Web CI`;
- `Playable Candidate Gate`;
- `Windows Compatibility Gate`;
- `Living World Integration Gate`;
- `Release Reproducibility Gate`.

Связанные профильные тесты должны проходить до запуска полного набора.
