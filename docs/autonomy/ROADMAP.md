# Дорожная карта автономной разработки

## Правила

Каждый этап имеет один из статусов:

- `planned` – запланирован;
- `active` – активен;
- `blocked` – заблокирован;
- `done` – завершён с подтверждением;
- `superseded` – заменён более актуальным решением.

Фактический GitHub и результаты проверок имеют приоритет над этой записью. Если состояние изменилось, дорожная карта обновляется по фактам.

## Текущий этап

### Стабильность Shared World Kernel

- Статус: `active`
- Результат этапа: Каноническое SQLite-ядро общего мира сохраняет подтверждённые свойства текущего `main` и готово к следующему адаптерному срезу.
- Критерий завершения: `pytest -q` проходит на одном точном рабочем SHA, а инварианты из `README.md` и `PROJECT_CHARTER.md` сохраняются.
- Зависимости: Python 3.12+, SQLite, pytest и существующее детерминированное ядро в `src/samseberpg`.
- Блокеры: Перед продуктовой реализацией требуется свежая сверка более новых рабочих веток и открытых PR с текущим `main`.
- Подробный план: `README.md` и существующие спецификации/планы в `docs/superpowers/`.

## Следующие этапы

1. Сверить более новые активные ветки и запросы на слияние с состоянием `main`, чтобы выбрать фактическую продуктовую линию без потери уже выполненной работы.
2. После подтверждения зелёного ядра продолжить Discord gameplay adapter (`/look`, `/me`, `/act`), сохраняя симуляционный пакет независимым от Discord и LLM SDK.

## Завершённые этапы

Текущий `main` содержит подтверждённое Shared World Kernel с постоянным SQLite-состоянием, идемпотентными действиями, общим состоянием игроков и детерминированными расписаниями NPC; эта установка управляющего слоя сама по себе не меняет продуктовые файлы.

## Правила изменения дорожной карты

ChatGPT может самостоятельно:

- отметить этап завершённым при наличии подтверждённых доказательств;
- разбить слишком крупную задачу на самостоятельные проверяемые части;
- переставить ближайшие задачи, если подтверждённый блокер изменил зависимости;
- добавить найденный дефект или технический долг, который мешает текущей цели;
- заменить устаревший пункт статусом `superseded` с кратким основанием;
- уточнить двусмысленный критерий завершения без расширения продуктовой цели.

Изменение продуктовой цели и значительное расширение области требуют решения владельца.
