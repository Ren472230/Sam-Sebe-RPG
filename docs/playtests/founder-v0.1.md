# Founder Playtest v0.1

## Что проверяем

Один вопрос:

> Хочется ли игроку самостоятельно пробовать необычные действия, когда мир системно отвечает на них, а устойчивое поведение превращается в персональную механику?

Это не тест количества контента, NPC-диалогов, экономики или multiplayer.

## Два режима

### A. Systems-only

Запуск без LLM:

```bash
sam-sebe-rpg --db playtests/founder-systems.db
```

Проверяет simulation → event log → behavior → achievement → ability.

**Не считается полноценной проверкой свободы ввода**, потому что игрок использует ограниченный командный язык.

### B. Free-input

Запуск с локальной Ollama-моделью:

```bash
sam-sebe-rpg --db playtests/founder-free.db --ollama-model <model>
```

Это основной режим для проверки продуктовой гипотезы. LLM только преобразует текст в `CanonicalAction`; исход и state mutation остаются детерминированными.

## Перед сессией

- Использовать новую БД.
- Не смотреть thresholds progression во время игры.
- Не открывать тесты/код для поиска оптимального пути.
- Разрешено пользоваться только `help` и тем, что видно через `осмотреться`.
- Сессия: 30–60 минут.

## Во время сессии

В отдельной заметке фиксировать только моменты, не прерывая игру:

```text
WHAT_IF: что захотелось попробовать самостоятельно
REPHRASE: действие пришлось переформулировать
SURPRISE: мир ответил неожиданно, но логично
CONFUSION: непонятно, почему произошёл результат
PROGRESSION: что почувствовал в момент открытия способности
```

Особенно важно не превращать тест в поиск способа «выбить ачивку».

## После сессии

Снять технический отчёт:

```bash
python scripts/playtest_report.py playtests/founder-free.db
```

И сохранить JSON evidence:

```bash
python scripts/playtest_report.py playtests/founder-free.db --json > playtests/founder-free-report.json
```

Ответить себе без попытки оправдать проект:

1. Сколько раз реально возникло «а что если…?» без подсказки интерфейса?
2. Показалась ли новая способность логичным следствием биографии персонажа?
3. Захотелось ли сразу проверить новую способность в другой ситуации?
4. Был ли мир игрой с правилами или ощущался AI roleplay-чатом?
5. В какой момент стало скучно или возникло желание спросить «какой следующий квест?»

## PASS для следующей итерации

Нужны одновременно:

- минимум 5 самостоятельных `WHAT_IF` за сессию;
- хотя бы один progression moment воспринимается как причинное следствие поведения;
- после unlock игрок добровольно пытается повторно/иначе применить новую возможность;
- системные ограничения ощущаются понятными, а не случайными запретами;
- свободный ввод достаточно часто превращается в корректные canonical actions, чтобы не ломать поток игры.

## ITERATE

Продолжаем, но не расширяем мир, если:

- core loop интересен, но parser часто требует переформулировок;
- progression понятен, но ощущается слишком grindy;
- игрок экспериментирует, но система недостаточно различает контекст/вариативность;
- способность интересна, но момент её появления плохо объяснён.

Исправляем конкретный bottleneck и повторяем такой же маленький тест.

## STOP / серьёзный пересмотр

Негативные сигналы:

- игрок в основном ждёт списка задач/квестов;
- «свобода» сводится к красивым LLM-описаниям без системных различий;
- Behavior Engine ощущается скрытой шкалой «повтори N раз»;
- после unlock нет желания проверить способность;
- интерес существует только пока удивляет сам факт наличия AI.

## Главное правило решения

Не добавлять город, десятки NPC, combat или economy, чтобы «оживить» плохой результат этого теста. Если базовый момент `experiment → evidence → personal mechanic → new experiment` не работает в маленьком мире, масштабирование только увеличит стоимость ошибки.
