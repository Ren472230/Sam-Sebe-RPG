# Telemetry Foundation v1

## Цель

Минимальная телеметрия для первых 5–20 человеческих игровых сессий. Она отвечает только на вопросы, которые помогают понять ранние точки отваливания и видимость Living World.

## Продуктовые вопросы

1. Запустилась ли игровая сессия?
2. Сделал ли игрок первое движение?
3. Нашёл ли игрок хотя бы одно взаимодействие?
4. Начал ли игрок диалог с NPC и какой безопасный провайдер реально ответил?
5. Принял ли игрок квест Орена?
6. Завершил ли игрок квест Орена?
7. Использовал ли игрок WAIT?
8. Увидел ли игрок хотя бы одно событие Living World?
9. Завершил ли игрок Stream Slice?
10. Возникали ли ошибки веб-клиента?

## События

| Событие | Смысл |
| --- | --- |
| `game_started` | Каноническая сессия создана и первый snapshot успешно получен. |
| `first_move` | Первое фактическое движение игрока в текущей странице. |
| `first_interaction` | Первое найденное и использованное взаимодействие. |
| `npc_dialogue_started` | Первый успешный обмен в открытом диалоге с NPC; только здесь известен фактический провайдер. |
| `quest_accepted` | Сервер подтвердил принятие квеста. |
| `quest_completed` | Сервер подтвердил сдачу квеста. |
| `wait_used` | Сервер подтвердил WAIT и клиент обновил snapshot. |
| `living_world_event_seen` | Событие Living World вошло в видимый пользователю список последних событий. |
| `stream_slice_completed` | В stream-режиме игрок успешно передал хлеб Орену, то есть дошёл до финального причинного шага Stream Slice перед проверкой persistence. |
| `client_error` | Ошибка клиентского выполнения или игрового запроса; текст, stack trace и пользовательский ввод не передаются. |

## Разрешённые свойства

- `app_version`
- `commit_sha`
- `mode`: `normal` или `stream`
- `location_id`
- `npc_id`
- `quest_id`
- `dialogue_provider`: `openai` или `fallback`
- `elapsed_bucket`
- `viewport_class`

Любые другие поля адаптер отбрасывает. Свободный текст диалога, prompt, message, email, ключи и произвольные свойства в payload не проходят.

## Архитектура и отказоустойчивость

`web/src/telemetry.ts` является единственной точкой отправки. Без конфигурации адаптер работает как no-op. Вызовы не ожидают сеть и проглатывают ошибки транспорта, поэтому недоступность аналитики не блокирует gameplay.

Для PostHog используется прямой HTTPS capture endpoint с отдельным случайным session ID. События отправляются с `$process_person_profile: false`, чтобы не создавать person profile. Cookies и браузерные credentials этим адаптером не отправляются.

## Конфигурация

Телеметрия включается только когда в Vite-конфигурации одновременно заданы:

- `VITE_POSTHOG_KEY` – project token PostHog;
- `VITE_POSTHOG_HOST` – HTTPS ingestion host PostHog.

Опционально:

- `VITE_APP_VERSION`;
- `VITE_COMMIT_SHA`.

Никогда не помещать в Vite-переменные `OPENAI_API_KEY`, personal API keys или серверные secrets: значения `VITE_*` попадают во frontend bundle.

Перед первой человеческой сессией в текущем PostHog-проекте требуется отключить IP data capture на уровне проекта: Settings > Project > Privacy > IP data capture. На момент подготовки v1 проект сообщал `anonymize_ips: false`, поэтому production ingestion пока считается privacy-blocked.

## Первая аналитика после подтверждённого ingestion

Основная воронка:

`game_started → first_interaction → quest_accepted → quest_completed`

Дополнительно достаточно считать:

- `wait_used`;
- `living_world_event_seen`;
- `client_error`;
- распределение `npc_dialogue_started` по `dialogue_provider`.

Сохранённые insights следует создавать после того, как эти события реально появились в PostHog schema. До этого пустой dashboard является корректным стартовым состоянием.

## Ограничения v1

- Анонимный session ID живёт только в текущей загрузке страницы. Reload создаёт новую аналитическую сессию и может разорвать воронку между событиями до и после reload.
- `first_move` и `first_interaction` являются page-session milestones, а не долговременными пользовательскими свойствами.
- `living_world_event_seen` означает попадание события в видимый список, а не доказательство того, что человек прочитал строку.
- `client_error` показывает факт ошибки, но специально не содержит текста ошибки или stack trace ради минимизации данных.
- Аналитика v1 предназначена для малой серии ручных тестов. Сегментации, retention, replay и сложные пользовательские профили пока не нужны.
